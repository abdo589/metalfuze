- Import uploaded brand imagery through Lovable Assets pointers; keep only the resized favicon in public so branding stays lightweight and tab icons remain directly accessible.
- Light and dark mode are both driven by the CSS variables in `src/styles.css` (`:root` = light, `.dark` = dark); never hardcode colors in components so both modes stay correct.
- The chosen mode is saved in localStorage and applied by an inline `<head>` script before paint; keep that script and `suppressHydrationWarning` on `<html>` when editing the root shell.
- AI assistant: client sends current dashboard projects to /api/chat (server route, Lovable AI Gateway Responses via src/server/ai); chat threads live in localStorage (src/lib/threads.ts) because project data is browser-local too. The server also fetches a whole-system snapshot (src/server/system-context.ts: hr_records, employees, residencies, leave, attendance, settlements) with the caller's own session so RLS decides what the advisor sees — never use the admin client for that snapshot. Attachments: the advisor reads PDFs and pictures inline plus text files inlined as text; the browser reads them with FileReader (the site CSP refuses fetching blob:/data: URLs) and saved threads keep only file names, so keep that file-bytes stripping in src/components/AssistantChat.tsx. The floating launcher (src/components/AssistantFab.tsx, mounted in the root shell) only shows where assistantAllowed(role) in src/lib/permissions.ts matches RoleGuard's allowed lists.
- Company PDFs use a shared browser-only export helper and button: capture the print layout and paginate at row boundaries to omit browser URL footers and avoid cutting rows.
- Use the shared i18n store and translation function for labels, dates, dialogs and export headings. In English mode, src/components/AutoTranslate.tsx translates remaining on-screen Arabic (incl. names/notes) display-only via /api/translate with a device cache; never write translations back to stored data, inputs or credentials.
- Period project reports select projects whose scheduled dates overlap the calendar period (Monday-start weeks); undated projects remain included, and financial/progress figures are explicitly current cumulative snapshots, not fabricated historical movements.
- Employees and attendance live in Lovable Cloud tables (employees, attendance_devices, attendance_logs); ZKTeco devices push via ADMS to the fixed /iclock/cdata route, which stores punches only for admin-approved serial numbers.
- Remote (phone) attendance: employees use secret per-employee links at /checkin/$token (outside AuthGate) posting to /api/public/checkin; supervisors use an admin-checked server fn. Both share src/lib/remote-checkin.server.ts, which enforces the work-site GPS radius, stores selfies in the private attendance-selfies bucket, and writes attendance_logs with device_sn 'REMOTE' — so one validation path serves both entry points.
- Self-registered project managers (role `manager`, auto-assigned by the on_self_signup trigger when signup metadata has self_signup=true; role-less accounts are treated the same) only open /my-projects, backed by mgr_projects/mgr_reports and the private project-files bucket (owner-only RLS, admins read) — keeps their data isolated from the main browser-local dashboard.
- Signed-in sessions end on inactivity via src/components/IdleSignOut.tsx, mounted in the root shell (src/routes/__root.tsx) beside AuthGate; keep it there so every signed-in page is covered, and never run it on /checkin/$token links, which employees open without accounts.
- MCP server lives in src/lib/mcp (one tool per file, OAuth via Lovable Cloud, caller-scoped client so existing permissions apply); the /mcp route is generated by mcpPlugin — never hand-edit it.
- Personal Outlook mail (/mail) uses the Microsoft Outlook App User Connector: each signed-in user connects their own mailbox; encrypted connection keys live server-only in app_user_connections and all Graph calls go through src/lib/outlook.functions.ts, so no user can read another mailbox.
- Executive summary (/executive) reads exec_snapshot, the shared store for admins and the CEO: their browsers load it (admins merge, keeping local edits on first load), follow it live via realtime, and upsert changes back (ExecSnapshotSync in root) — because project data is browser-local, this is how other devices see live figures.
- Router preloads pages on link hover/touch (defaultPreload "intent") and Query data stays fresh 60s — keeps page switches near-instant; set a shorter staleTime per query when data must be live.
- Database reads in the browser go through src/lib/read-cache.ts (installed in root): short-TTL, per-session keyed, cleared per table on writes — speeds repeat reads without stale data after saves.
- Developer role (app_role developer) only opens /dev: bug_reports inbox (user reports + auto-captured browser errors via src/components/BugReport.tsx) and account management; users.functions.ts server fns require developer — keeps account control with one person.
- Sign-in/sign-out audit: AuthGate/IdleSignOut log via src/lib/login-tracking.ts to a server fn that reads IP/location from request headers (not the browser) into login_events; only the developer reads it on /dev — always sign out through signOutTracked so logouts are recorded.
